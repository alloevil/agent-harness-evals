**agent-harness-evals** is a reconciliation layer over public AI evaluation leaderboards that exposes the model × agent-harness matrix model-only leaderboards hide — for engineers choosing which harness to run a given model in, and for anyone quoting a benchmark score who needs to know how much of it the scaffold produced.

The same model does not get the same score. On terminal-bench, `claude-opus-4.6` passes **58.0%** of tasks under Claude Code and **69.9%** under Droid; `gpt-5.3-codex` moves from **64.7%** (Terminus 2) to **77.3%** (Droid). Median cross-harness spread across 30 models: **11 points** — the same order of magnitude as a model-generation upgrade. Model leaderboards hide this variable. This project gives it an axis.

## What it is

Not another benchmark. An **aggregation and reconciliation layer** over benchmarks that already exist:

1. **Fetch** live leaderboard data (Epoch AI Benchmarking Hub, 75 benchmarks, refreshed ~daily, CC-BY) plus the HAL harness leaderboards.
2. **Normalize** model / scaffold / score semantics into one record schema — `(benchmark, model, scaffold, score)` — with **one model id across sources**: `claude-sonnet-4-5-20250929` (Epoch) and "Claude Sonnet 4.5 High (September 2025)" (HAL) both land on `claude-sonnet-4.5`, so cross-source rows join instead of fragmenting.
3. **Render** views no single leaderboard offers: the **model × harness matrix**, a **harness ranking** (share of each model's best score a harness retains), a **model ranking** (each model's best score and the harness that got it there), and **native-pairing boards** (FrontierSWE, frontiercode) where each model runs in its vendor's own CLI.

Existing cross-layer corpora ([Messier](https://arxiv.org/abs/2607.25891), [HAL](https://github.com/princeton-pli/hal-harness)) are one-off snapshots; live leaderboards are single-layer. This repo is the missing combination: **cross-layer and alive** — a scheduled `fetch → normalize → build` run keeps the page exactly as fresh as the upstream data, with zero evaluation cost.

## Record schema

Follows the reconciliation model of [Messier](https://arxiv.org/abs/2607.25891) (model, scaffold, environment, task, verifier), collapsed to benchmark granularity for sources that publish only aggregates.

| field | meaning |
|---|---|
| `benchmark` | canonical benchmark id |
| `model` / `model_raw` | canonical id, shared across sources (effort/date suffixes and provider prefixes stripped, `claude-*-4-5` → `claude-*-4.5`) / original |
| `scaffold` | agent harness; `""` = provider-default |
| `score`, `score_unit` | primary metric; `rate` = 0–1 comparable, `raw` = source units |
| `source`, `source_link` | provenance, down to per-run logs where upstream provides them |

## Status & limitations

- **Two harness sources.** Terminal-Bench (via Epoch) is the only *live*, machine-readable harness leaderboard. HAL adds a second, *historical* harness dimension — its leaderboard score tables are public HTML (only the traces are encrypted), covering 9 benchmarks with a different harness set (SWE-Agent, Browser-Use, CORE-Agent, …). SWE-bench pins a single harness (mini-swe-agent), so its official board is a model ranking, not a harness matrix.
- **Scores are aggregates, not trials.** Upstream publishes benchmark-level scores; `spread` is computed from those, with a per-model `n` and `stderr` where reported. n<3 spreads are dimmed.
- **Tool-layer comparisons** (tool A vs tool B under a fixed agent) have no public data source yet and are out of scope until one exists.
- **Messier is not yet downloadable.** The Messier paper (arXiv, still in anonymous review) and its code are public, but the dataset is only referenced as a "companion dataset" — no public download URL exists in the paper or its repo. Importing it is blocked on the paper's de-anonymized release, not on this repo.

## When to use it

- You have picked a model and need to know which agent harness gets the most out of it, or you are locked into a harness and need the best model for it.
- You are about to quote a benchmark score and want to know how much of it the scaffold produced: on the same benchmark, the same model can sit points away under a different harness.
- You want a reconciled `(benchmark, model, harness, score)` corpus without scraping several leaderboards and hand-matching model names.
- You want the history: one JSONL snapshot per day under `data/snapshots/`, which is what the [trend view](https://alloevil.github.io/agent-harness-evals/trend.html) reads.

## When NOT to use it

- **Not a measurement.** Nothing here is re-run. Every score was published by an upstream leaderboard and is republished with its source, so an upstream error is reproduced faithfully.
- **Not trial-level data.** Upstream publishes benchmark-level aggregates, so `spread` is a difference between published scores, not a paired per-task comparison.
- **Not equally solid on every board.** A median spread is only published where some model was measured under 3+ harnesses; elsewhere a "spread" would be a single pairwise difference, and `n` is shown so you can see which is which.
- **Not a tool-layer comparison.** Tool A vs tool B under a fixed agent has no public data source yet.
- **No contamination or saturation labels.** This project does not judge whether a benchmark still discriminates; it reports what harnesses did on it. See [Status & limitations](#status--limitations).

## FAQ

**Does this project run benchmarks or agents?** No. It downloads scores that public leaderboards already published, reconciles the model and harness names behind them, and pivots them into per-benchmark matrices. There is no evaluation cost, no API key and no model access anywhere in the pipeline — which is also why every limitation of the upstream boards is inherited here.

**What counts as a harness?** The scaffold around the model: agent loop, tool set, prompts, retry policy, step budget — Claude Code, Codex CLI, Droid, OpenHands, mini-SWE-agent, Terminus and so on. In the record schema it is the `scaffold` field; an empty scaffold means the provider default, kept distinct from a named harness.

**Why does a benchmark sometimes show no median spread?** Because no model on that board was measured under three or more harnesses. With two harnesses the gap is one pairwise comparison that a median cannot make more reliable, so the number is withheld instead of dressed up as a spread. The matrix is still shown, with each model's `n`.

**How fresh is the site?** `.github/workflows/refresh.yml` runs the whole pipeline daily at 05:23 UTC and commits only when something changed, so the page, its JSON-LD, `claims.json` and the llms files are exactly as fresh as the upstream data and always agree with each other.

**Can I reuse the data?** The code and derived views are MIT licensed and the snapshots are committed here, so cloning is the simplest route. The underlying scores belong to their publishers — Epoch AI's dump is CC-BY and asks for credit, HAL's tables belong to the HAL maintainers — so keep those attributions when you republish.
